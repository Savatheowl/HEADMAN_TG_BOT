# HEADMAN_TG_BOT

Асинхронный Telegram-бот для доставки расписания занятий колледжа. Источник данных — PDF-файлы, опубликованные в теме VK. Система самостоятельно обнаруживает изменения, разбирает документы в структурированный вид, хранит их в SQLite и уведомляет затронутых пользователей.

## Обзор

| Параметр | Значение |
|----------|----------|
| Язык / рантайм | Python 3.11, `asyncio` |
| Telegram-фреймворк | aiogram 3.x (long polling) |
| Хранилище | SQLite через SQLAlchemy 2.0, режим WAL |
| Парсинг | pdfplumber (табличный разбор страниц PDF) |
| Получение данных | Playwright + Chromium (headless) |
| Развёртывание | Docker / Docker Compose |
| Входящие порты | не требуются (только исходящие соединения) |

Ключевые свойства:

- **Инкрементальное обновление.** Файлы скачиваются и разбираются только при фактическом изменении содержимого (сравнение SHA-256 и версионирование).
- **Атомарная замена данных.** Занятия одной версии файла заменяются целиком в одной транзакции (`DELETE` + bulk `INSERT`).
- **Изоляция чтения и записи.** Парсер выполняется в рабочем потоке, бот параллельно читает БД; конфликты исключает WAL.
- **Идемпотентность.** Повторный запуск цикла обновления на неизменённых данных не приводит к записи и рассылкам.

## Архитектура

```
                    ┌──────────────────────────────────────────────┐
                    │                  Процесс бота                │
                    │                                              │
  VK-тема ─────────►│  Downloader ──► файлы ──► Parser ──► SQLite  │
  (PDF-документы)   │  (Playwright)   на диске  (поток)      ▲     │
                    │       ▲                                │     │
                    │       └──── schedule_updates_loop ─────┤     │
                    │                                        │     │
  Telegram API ◄───►│  aiogram Dispatcher ◄── кэш (TTL) ◄────┘     │
  (long polling)    │  Router · FSM · Middleware                   │
                    └──────────────────────────────────────────────┘
```

Приложение — один асинхронный процесс. Точка входа `main.py` вызывает `src.bot.main()`, который:

1. читает конфигурацию и проверяет `BOT_TOKEN`;
2. инициализирует БД и применяет лёгкие миграции;
3. регистрирует команды и описания бота через Telegram API;
4. запускает фоновую задачу `schedule_updates_loop`;
5. подключает middleware и роутер, удаляет webhook (`drop_pending_updates=True`) и запускает long polling.

### Модули

| Модуль | Ответственность |
|--------|-----------------|
| `src/bot.py` | Обработчики, inline-клавиатуры, FSM-сценарии, форматирование, рассылки, фоновый цикл |
| `src/config.py` | Загрузка настроек: переменные окружения ОС → `.env` → значения по умолчанию |
| `src/database.py` | ORM-модели, версионирование файлов, CRUD, миграции, кэш выборок |
| `src/downloader.py` | Получение документов из VK, повторные попытки, хэширование, прокси |
| `src/parser.py` | Разбор PDF в записи `ScheduleLesson`, определение дня недели по геометрии страницы |

### Модель параллелизма

- Бот и фоновый цикл работают в одном event loop.
- Блокирующий парсинг PDF вынесен в поток: `asyncio.to_thread(parse_schedule_files, ...)`.
- Скачивание использует несколько страниц одного браузерного контекста, ограниченных `asyncio.Semaphore` (по умолчанию 3).
- SQLite открывается с `check_same_thread=False`, `PRAGMA journal_mode=WAL` и `PRAGMA busy_timeout=5000`.
- Кэш выборок защищён `threading.RLock`.

## Конвейер обновления расписания

Цикл выполняется при старте и далее каждые `UPDATE_INTERVAL_MINUTES` (функция `update_schedule_once`).

### 1. Получение (`downloader.py`)

1. Открывается тема VK. Хосты перебираются по порядку (`vk.ru`, затем `vk.com`) до первого успешного ответа.
2. Навигация выполняется с повторами: до 3 попыток, таймаут 60 с, паузы между попытками 5 и 15 с.
3. На странице темы собираются ссылки документов (селектор `a.page_doc_title`); со страницы каждого документа извлекается прямая ссылка на PDF.
4. PDF загружается в память, вычисляется SHA-256.
5. Если хэш уже присутствует в БД, файл пропускается. Иначе он записывается на диск и регистрируется через `register_file`: для нового имени создаётся версия 1, для изменившегося содержимого версия увеличивается на 1.

При необходимости весь исходящий трафик Chromium направляется через прокси (`PROXY_URL`).

### 2. Разбор (`parser.py`)

Обрабатываются только файлы с `KURS` в имени. Номер курса извлекается из имени регулярным выражением `_(\d+)_KURS`. Одна страница PDF соответствует одной группе.

Для каждой страницы:

1. Название группы извлекается шаблоном `Группа\s+...` из текста страницы.
2. Через `page.find_tables()` берётся таблица занятий; отображение «колонка → поле» определяется по строке заголовка (`время`, `неделя`, `дисциплина`, `ауд`, `вид занятия`, `преподаватель`).
3. День недели строки определяется по **повёрнутым вертикальным подписям**: слова читаются в обратном порядке, сопоставляются с названиями дней, границей между днями служит середина между центрами соседних подписей.
4. Если ведущие подписи (например, «ПОНЕДЕЛЬНИК») нарисованы векторными кривыми и текстом не извлекаются, недостающие метки восстанавливаются экстраполяцией с тем же шагом (`_fill_missing_leading_days`).
5. Ошибка на отдельной странице логируется и не прерывает обработку файла.

Файл разбирается, если таблица занятий пуста либо `parsed_version != version`. Запись выполняется методом `replace_lessons_for_version` в одной транзакции. Версия отмечается как разобранная (`mark_parsed`) только если получено хотя бы одно занятие; пустой результат оставляет файл в очереди на повторный разбор.

### 3. Публикация изменений

- Кэш выборок расписания сбрасывается после замены данных версии.
- Для каждого курса, у которого версия действительно была разобрана (`status = "parsed"`), формируется список затронутых групп, и студентам этого курса отправляется уведомление (до 6 групп в тексте, остальные сворачиваются в «и ещё N»).
- Рассылка учитывает ограничения Telegram: пауза 50 мс между сообщениями, обработка `TelegramRetryAfter` с одной повторной попыткой, пропуск недоступных пользователей (`TelegramForbiddenError`, `TelegramNotFound`).

Любое исключение внутри цикла перехватывается и логируется, фоновая задача продолжает работу.

## Модель данных

| Таблица | Назначение | Ключевые поля |
|---------|------------|---------------|
| `file_versions` | Учёт скачанных файлов | `name` (unique), `version`, `parsed_version`, `file_hash` (SHA-256), `size`, `source_url` |
| `schedule_lessons` | Занятия | `file_version_id` (FK, `ON DELETE CASCADE`), `course`, `group_name`, `day_of_week`, `time`, `week`, `discipline`, `audience`, `lesson_type`, `teacher` |
| `bot_users` | Пользователи | `telegram_id` (unique, `BIGINT`), `group_name`, `role`, `is_active`, `last_seen_at` |
| `user_actions` | Журнал действий для статистики | `user_id` (FK), `action`, `payload`, `created_at` |
| `report_bans` | Запрет отправки обращений | `telegram_id` (PK), `banned_at` |

Составной индекс `ix_lessons_group_day (group_name, day_of_week, time)` обслуживает основной сценарий чтения.

**Миграции.** `Database.init_db()` выполняет `create_all` и идемпотентные `ALTER TABLE`-миграции: добавление `file_versions.parsed_version`, `bot_users.role`, `schedule_lessons.course` с обратным заполнением курса по имени файла.

**Кэширование.** `get_lessons_for_group` кэширует выборки в памяти по ключу `(группа, неделя, день)` с TTL `CACHE_TTL_SECONDS`. Инвалидация происходит после импорта новой версии.

## Ролевая модель

Роль хранится в `bot_users.role` и приводится к числовому уровню доступа.

| Уровень | Коды ролей | Возможности |
|:-------:|------------|-------------|
| 0 | `student` | Просмотр расписания, настройки, обращения администратору |
| 1 | `teacher`, `trusted` | Дополнительно: объявления для своего курса или для всех курсов |
| 2 | `admin` | Дополнительно: админ-панель (статистика, рассылки, роли, ручное обновление) |
| 3 | `superuser` | Назначается только через `ADMIN_IDS`; выдаёт роли |

Идентификаторы суперпользователей задаются в конфигурации, остальные роли назначаются через админ-панель.

## Функциональность бота

**Пользовательские сценарии**

- Главное меню: «Сегодня», «Завтра», «Неделя». Для воскресенья «Завтра» показывает понедельник следующей недели.
- Панель расписания: переключение верхней и нижней недели, выбор дня, обзор недели. Группа кодируется в `callback_data`, поэтому навигация работает и для чужих групп.
- Просмотр расписания любой группы (курс → группа).
- Получение исходного PDF для своего курса.
- Смена группы с подтверждением.
- Обращения (проблема или предложение): сообщение пересылается главному администратору (`REPORT_ADMIN_ID`) с метаданными отправителя и кнопкой блокировки автора.

**Административные сценарии**

- Статистика: пользователи, активность, распределение по курсам.
- Рассылка: все пользователи или выбранный курс, с шагом подтверждения.
- Управление ролями через поиск пользователей.
- Принудительный запуск цикла обновления расписания.
- Объявления (для ролей уровня 1 и выше): свой курс или все курсы, с подтверждением.

**Определение чётности недели.** Чётная ISO-неделя считается верхней; флаг `WEEK_PARITY_FLIP=true` инвертирует соответствие. Расчёт использует локальное время процесса, поэтому в контейнере необходим корректный `TZ`.

**Служебные механизмы.** `ActionLogMiddleware` обновляет `last_seen_at` и пишет действия в `user_actions`. Многошаговые сценарии (рассылка, объявление, обращение, выдача роли) реализованы на FSM aiogram.

Команды, зарегистрированные в Telegram: `/start`, `/help`. Остальное управление выполняется через inline-кнопки.

## Конфигурация

Приоритет источников: **переменные окружения ОС → файл `.env` → значения по умолчанию**.

| Переменная | Обязательна | По умолчанию | Описание |
|------------|:-----------:|--------------|----------|
| `BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `ADMIN_IDS` | нет | пусто | Telegram-id суперпользователей через запятую или пробел |
| `REPORT_ADMIN_ID` | нет | первый из `ADMIN_IDS` | Получатель обращений пользователей |
| `DATABASE_PATH` | нет | `data/bot.db` | Путь к файлу SQLite |
| `DOWNLOAD_DIR` | нет | `downloads` | Каталог скачанных PDF |
| `UPDATE_INTERVAL_MINUTES` | нет | `60` | Период проверки источника |
| `CACHE_TTL_SECONDS` | нет | `3600` | TTL кэша выборок расписания |
| `WEEK_PARITY_FLIP` | нет | `false` | Инверсия соответствия чётности и верхней недели |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `PROXY_URL` | нет | пусто | Прокси для получения расписаний (`socks5://host:port`, `http://host:port`) |

Файл `.env` содержит секреты и исключён из git и из Docker-образа.

## Установка и запуск

Требования: Python 3.11+, токен бота.

```bash
git clone https://github.com/Savatheowl/HEADMAN_TG_BOT.git
cd HEADMAN_TG_BOT
git checkout dev

python3 -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium

cp .env.example .env                   # задать BOT_TOKEN и ADMIN_IDS
python main.py
```

При первом запуске создаётся БД; так как таблица занятий пуста, выполняется полное скачивание и разбор всех файлов.

Отдельные утилиты:

```bash
# получить файлы расписания
python src/downloader.py --url <VK_URL> --dir downloads [--concurrency 3]

# разобрать PDF в БД
python src/parser.py --dir downloads
```

## Развёртывание в Docker

Образ основан на `python:3.11-slim`, Chromium устанавливается через `playwright install --with-deps chromium` в `/ms-playwright`. Приложение запускается от непривилегированного пользователя `appuser`.

```bash
cp .env.example .env                   # задать BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

Параметры `docker-compose.yml`:

| Параметр | Значение | Назначение |
|----------|----------|------------|
| `restart` | `unless-stopped` | Автоматический подъём после сбоя или перезагрузки хоста |
| `init` | `true` | Корректная обработка сигналов и зомби-процессов Chromium |
| `shm_size` | `1gb` | Разделяемая память для Chromium |
| `env_file` | `.env` | Источник секретов и настроек |
| `TZ` | `Europe/Moscow` | Обязателен: от него зависят «Сегодня», «Завтра» и чётность недели |
| тома | `headman-data`, `headman-downloads` | Постоянное хранение БД и PDF |

Обновление: `git pull && docker compose up -d --build`. Данные в томах сохраняются.

### Резервное копирование и восстановление

```bash
# копирование
mkdir -p backup/data backup/downloads
docker run --rm -v headman-data:/data -v "$(pwd)/backup/data:/backup" alpine sh -c 'cp -a /data/. /backup/'
docker run --rm -v headman-downloads:/data -v "$(pwd)/backup/downloads:/backup" alpine sh -c 'cp -a /data/. /backup/'
cp .env backup/

# восстановление (при остановленном сервисе)
docker compose stop
docker run --rm -v "$(pwd)/backup/data:/data" -v headman-data:/backup alpine sh -c 'cp -a /data/. /backup/'
docker run --rm -v "$(pwd)/backup/downloads:/data" -v headman-downloads:/backup alpine sh -c 'cp -a /data/. /backup/'
docker compose start
```

## Эксплуатация и диагностика

### `sqlite3.OperationalError: unable to open database file`

Процесс не может создать файл БД из-за прав на запись. С именованными томами проблема не возникает. При использовании bind-mount каталоги должны быть доступны пользователю `appuser` (uid 1000):

```bash
chown -R 1000:1000 data downloads
```

### `[config] .env файл не найден: /app/.env`

Предупреждение штатное: `.env` исключён из образа через `.dockerignore`, значения поступают в контейнер через `env_file`.

### Таймаут при открытии темы VK

Симптом в логах: `Page.goto: Timeout ... navigating to "https://vk.ru/topic-..."`. Вероятная причина — фильтрация VK по IP зарубежных или датацентровых хостингов.

Проверка доступности из контейнера:

```bash
docker exec headman-bot python -c "import urllib.request as u; [print(h, u.urlopen('https://'+h+'/topic-61699714_47589048', timeout=20).status) for h in ['vk.ru','vk.com']]"
```

Если запросы зависают или возвращают 403, требуется исходящий трафик из РФ:

1. Указать `PROXY_URL` в `.env` (например, `socks5://host:1080`).
2. Выполнить `docker compose up -d --build`.
3. Убедиться в наличии строки `Использую прокси для egress` в логах.

Варианты прокси: VPS в РФ с SOCKS5 (например, `danted`), SSH-туннель `ssh -N -D 1080` с машины в РФ, коммерческий RU-прокси. Домен `m.vk.com` в списке хостов не используется: у него другая структура DOM, и текущие селекторы на него не рассчитаны.

### Файл не даёт занятий

Если разбор вернул ноль занятий, версия не помечается как разобранная, а в логах появляется предупреждение. Обычно это означает изменение формата PDF; требуется проверка логики в `parser.py`.

## Ограничения

- **Один экземпляр.** Архитектура рассчитана на единственный процесс: SQLite и кэш в памяти не предполагают горизонтального масштабирования.
- **Состояния FSM в памяти.** Незавершённые сценарии (рассылка, обращение) теряются при перезапуске.
- **Привязка к источнику.** Скачивание зависит от DOM страниц VK (CSS-селекторы и поля форм), парсинг — от структуры PDF (таблица, вертикальные подписи дней, строка «Группа ...»). Изменение любого из форматов требует правок кода.
- **Привязка к имени файла.** Курс определяется по шаблону `_N_KURS` в имени PDF.
- **Лицензия.** В репозитории не указана.

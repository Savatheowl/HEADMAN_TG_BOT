# HEADMAN_TG_BOT

Telegram-бот для показа расписания занятий колледжа. Пользователь выбирает курс и группу, бот показывает расписание на день/неделю с переключением между верхней и нижней неделями. Расписание автоматически скачивается из VK-темы и обновляется в фоне.

## Стек

- **aiogram 3.x** — Telegram-бот (асинхронный)
- **SQLAlchemy + SQLite** — хранение расписания, пользователей и статистики (режим WAL)
- **pdfplumber** — извлечение занятий из PDF
- **Playwright** — скачивание файлов расписания из VK

## Структура

```
main.py                 — точка входа (asyncio.run(main()))
Dockerfile              — образ для деплоя (Python 3.11 + chromium для Playwright)
docker-compose.yml      — запуск бота: env, volume'ы, restart policy
.dockerignore           — исключения из билд-контекста
src/
  bot.py                — бот: обработчики, inline-клавиатуры, форматтеры, фоновое обновление
  config.py             — класс Config: чтение .env (приоритет env ОС > .env > fallback)
  database.py           — SQLAlchemy: таблицы, версионирование файлов, CRUD, миграции
  downloader.py         — Playwright: скачивает PDF из VK-темы, SHA-256, качает только изменённое
  parser.py             — pdfplumber: парсинг PDF (1 страница = 1 группа), bulk-запись
tests/
  test_bot.py           — интеграционные проверки против реальной БД
data/                   — SQLite-файл бота
downloads/              — скачанные PDF
```

## Как работает

1. **Downloader** (`src/downloader.py`) открывает VK-тему, собирает ссылки на документы, по прямой ссылке качает PDF в память и сравнивает SHA-256 с БД — качает только файлы, которые действительно изменились.
2. **Parser** (`src/parser.py`) разбирает только те версии, которые ещё не отмечены как распарсенные (`parsed_version != version`). День недели определяется по повёрнутым вертикальным подписям в PDF. Занятия одной версии заменяются целиком за одну транзакцию (delete + bulk insert).
3. **Бот** (`src/bot.py`) показывает главное меню: «Сегодня» / «Завтра» (быстрый переход на нужный день, воскресенье показывается понедельником следующей недели), «📅 Неделя» (расписание на текущую неделю), «Чужое расписание» (курс → группа → панель группы), «📄 PDF расписания» (отправка файла-оригинала для своего курса), «Настройки» (смена группы студента с подтверждением и «📮 Сообщить о проблеме / предложении» — отправка текста главному админу). Панель расписания: переключение верхняя/нижняя неделя, выбор дня, «📅 Неделя», «← Назад» (в главное меню). Группа кодируется в callback панели, поэтому навигация по дням работает и на чужом расписании. Чётная ISO-неделя = верхняя (инвертируется флагом `WEEK_PARITY_FLIP`). Подменю возвращаются кнопками «← Назад».
4. **Роли и админ-панель.** Уровни ролей: студент (0) → староста/преподаватель (1) → админ (2) → суперпользователь (3). Суперюзеры задаются в `ADMIN_IDS` (`.env`), остальные роли раздаёт админ. Меню рендерится с учётом ролей: старосте видна кнопка «📢 Объявление», админу — «⚙️ Админ-панель». Админ-панель: статистика (пользователи, курсы, действия), рассылка (все/по курсам → текст → подтверждение → `send_to_users`), выдача ролей через поиск пользователей, кнопка ручного обновления расписания. Объявления старосты: свой курс или все курсы → текст → подтверждение.
5. **Кэш расписания.** `get_lessons_for_group` кэширует выборки в памяти (`_lessons_cache`) с TTL `cache_ttl_seconds`; кэш сбрасывается после импорта новой версии расписания (`invalidate_lessons_cache` в `replace_lessons_for_version`).
6. **Фоновый цикл** (`schedule_updates_loop`) раз в `UPDATE_INTERVAL_MINUTES` проверяет VK и обновляет БД. Если новые версии файлов реально распарсились (`status="parsed"`), всем студентам соответствующих курсов рассылается умное уведомление (`notify_course_update`) с перечнем групп, где есть изменения (первые ~6 + «и ещё N»).
7. **Сообщения о проблеме/предложении.** В «Настройках» кнопка «📮 Сообщить о проблеме / предложении» (скрыта для забаненных). Пользователь пишет текст, бот пересылает его главному админу (`REPORT_ADMIN_ID`, по умолчанию первый из `ADMIN_IDS`) с именем, username, группой, TG id и временем отправки. Под письмом — кнопка «🚫 Забанить автора»: дальше текст этого пользователя больше не принимается (таблица `report_bans`), и кнопка в настройках у него исчезает.

База данных: `file_versions` (контроль версий), `schedule_lessons`, `bot_users` (регистрация, роли), `user_actions` (статистика), `report_bans` (бан на отправку сообщений о проблеме).

## Команды

```bash
# запуск бота
python main.py

# скачать расписания отдельно
python src/downloader.py --url <VK_URL> --dir downloads

# распарсить PDF в БД отдельно
python src/parser.py --dir downloads

# интеграционные тесты
.venv/bin/python tests/test_bot.py
```

Конфигурация — в `.env` (см. `.env.example`): `BOT_TOKEN`, `DATABASE_PATH`, `UPDATE_INTERVAL_MINUTES`, `DOWNLOAD_DIR`, `WEEK_PARITY_FLIP`, `CACHE_TTL_SECONDS`, `ADMIN_IDS` (telegram id суперпользователей через запятую/пробел), `REPORT_ADMIN_ID` (главный админ для сообщений о проблеме; если пусто — берётся первый из `ADMIN_IDS`) и др.

## Деплой в Docker

Бот работает через исходящий long polling — внешние порты не нужны. Конфигурация передаётся переменными окружения: `docker compose` автоматически читает `.env` (`env_file`), а `src/config.py` даёт переменным окружения приоритет над файлом `.env`.

Сборка и запуск:

```bash
# на сервере (Ubuntu 22.04/24.04), после установки Docker Engine + compose plugin:
git clone https://github.com/Savatheowl/HEADMAN_TG_BOT.git
cd HEADMAN_TG_BOT
git checkout dev
cp .env.example .env          # вписать BOT_TOKEN и ADMIN_IDS
mkdir -p data downloads
docker compose up -d --build
docker compose logs -f
```

Обслуживание:

```bash
docker compose ps             # статус
docker compose logs -f        # логи
docker compose restart        # перезапуск
docker compose down           # остановка (данные в ./data и ./downloads сохраняются)
# обновление после git pull:
docker compose up -d --build
```

- `restart: unless-stopped` — бот сам поднимется после перезагрузки сервера.
- `env_file: .env` — токен и `ADMIN_IDS` живут только в `.env` на сервере (в `.gitignore`).
- Volume'ы `./data` и `./downloads` привязаны к папкам проекта — БД и PDF сохраняются между перезапусками, их легко бэкапить (tar этих папок + `.env`).
- `TZ=Europe/Moscow` — обязателен: расчёт «Сегодня/Завтра/неделя» зависит от локального времени сервера.
- `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright` в `Dockerfile` — чтобы chromium был виден не-root пользователю.
- Первый запуск стартует с чистой БД: расписания скачаются сами, пользователи зарегистрируются заново.
